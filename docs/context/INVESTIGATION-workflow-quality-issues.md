## Issue 1: Wrong Date in Answer

### Symptoms
- Answer discusses "June 7-8, 2025" events
- Query was asked on December 7, 2025
- "Next weekend" should be December 13-14 or December 20-21, 2025

### Investigation
- [x] Check if current date is passed to LLM - **NO, IT IS NOT**
- [x] Check sub-query for date resolution - Not relevant, root cause found
- [x] Check if system prompt includes date context - **NO DATE CONTEXT**

### Root Cause Found
**File**: `src/orchestration/planner.service.ts` line 1279

The `buildPlannerSystemPrompt()` function does NOT include the current date:
```typescript
return `You are a research planning agent...`
// NO MENTION OF CURRENT DATE!
```

The LLM has no temporal context when planning or synthesizing.

### Proposed Fix
Add current date to the system prompt:
```typescript
private buildPlannerSystemPrompt(availableTools: ToolDefinition[]): string {
  const currentDate = new Date().toLocaleDateString('en-US', {
    weekday: 'long',
    year: 'numeric',
    month: 'long',
    day: 'numeric'
  });

  return `You are a research planning agent. Today's date is ${currentDate}.
  ...
  `;
}
```

### Evidence
From the answer in session 41758c28:
```
If today is **Monday, June 3, 2025**, next weekend would be **June 7–8, 2025**.
```

The LLM guessed a date because it had no context.

## Issue 2: Irrelevant Knowledge Sources

### Symptoms
Sources include completely unrelated prior research:
- "What is the current time in Tokyo?"
- "What is TypeScript 5.7 release date?"
- "What is 3+3?"
- "What is 2+2?"
- "Capital of France"

### Root Cause Analysis
**File**: `src/knowledge/knowledge-search.service.ts`

The `searchPriorResearch()` method uses PostgreSQL full-text search:
```sql
WHERE search_vector @@ plainto_tsquery('english', $1)
```

The query "what is happening in aarhus next weekend" gets tokenized to:
- "what", "is", "happening", "aarhus", "next", "weekend"

Common words like "what" and "is" match almost every prior query.

**Problem**: No minimum relevance score threshold is applied.

### Proposed Fix
Add minimum score filtering in `searchHybrid()`:
```typescript
// Filter results below threshold
const MIN_RELEVANCE_THRESHOLD = 0.3;
return merged
  .filter(r => r.score >= MIN_RELEVANCE_THRESHOLD)
  .slice(0, maxResults);
```

## Issue 3: Abandoned Synthesis Phase

### Symptoms
From graph API:
```json
{
  "id": "phase-235303a1-1611-493a-beee-3530822d2638",
  "name": "Synthesis & Answer Generation",
  "status": "pending",
  "duration": null
}
```

Phase was created but never executed (status stayed "pending").

### Root Cause Found
**File**: `src/orchestration/orchestrator.service.ts` lines 376-383, 539-617

**The Problem**: Race condition in decomposed query execution.

1. Each sub-query creates its own plan with synthesis phase via `createPlan()` (auto-adds with status="pending")
2. Sub-queries execute in parallel via `Promise.all()` at line 345
3. After all sub-queries complete, `synthesizeFinalAnswer()` is called directly (line 376-383)
4. This method uses `llmService.chat()` directly, bypassing the planned synthesis phases
5. The auto-generated synthesis phases are never executed → remain "pending"

```typescript
// Line 376-383: Uses direct LLM synthesis, NOT the planned synthesis phases
const finalAnswer = await this.synthesizeFinalAnswer(
  decomposition.originalQuery,
  decomposition.subQueries,
  subQueryResults,
  logId,
);
```

### Evidence
- 4 Synthesis phases exist: 1 "pending" (abandoned), 3 "completed" (sub-query syntheses)
- The final answer was generated by `synthesizeFinalAnswer()` which bypasses phase execution
- The abandoned phase was created by `ensureSynthesisPhase()` at `planner.service.ts:761-801`

### Proposed Fix
This is a **cosmetic issue** - the workflow completes correctly. Options:
1. Don't auto-add synthesis phase for decomposed queries
2. Mark abandoned phases as "skipped" instead of leaving "pending"
3. Clean up unused phases after synthesis completes

**Priority**: Low - doesn't affect functionality
